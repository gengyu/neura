# Neura MVP v0.1 归档

本文档从主需求文档 `prd.md` 中归档而来。

主 PRD 负责定义 Neura 的产品定位、架构语义和长期系统边界。

本文件仅保留第一版 MVP 范围、暂不包含内容和验收标准，供后续实现计划参考。

---

# 1. MVP 范围

第一版目标不是做完整平台，而是跑通两个最小闭环。

输入闭环：

```text
输入插件 → Neura Runtime → Agent Loop → 记忆 / 状态 / 日志
```

输出闭环：

```text
Neura Runtime → 输出决策 → 输出插件 → 外部表达
```

## 1.1 MVP 必须包含

### 1. Neura Runtime

支持启动、停止、查看状态。

```bash
neura start
neura stop
neura status
```

### 2. CLI 输入插件

用户可以通过命令行输入信息。

```bash
neura input "我想做一个常驻运行的智能体"
```

### 3. CLI 输出插件

Neura 可以在需要表达时，通过命令行输出信息。

### 4. SQLite 本地存储

保存：

```text
输入事件
任务
记忆
插件配置
日志
```

### 5. Agent Loop

支持基础处理：

```text
接收输入
生成摘要
生成标签
判断是否记忆
写入记忆
更新任务与状态
```

### 6. 插件状态

能够查看输入插件和输出插件状态。

### 7. 日志

记录输入处理、记忆沉淀和输出表达。

---

# 2. MVP 暂不包含

第一版不做：

```text
完整 Web 后台
桌面客户端
移动端 App
插件市场
多用户系统
复杂账号系统
多设备同步
复杂知识图谱
自动执行高风险操作
本地大模型
复杂权限 UI
```

这些以后都可以做，但不是第一阶段重点。

第一阶段重点是：

```text
让 Neura 真的跑起来
让信息真的能进入
让记忆真的能沉淀
让必要的信息真的能表达
```

# 3. 验收标准

MVP 完成时，必须满足以下条件。

## 3.1 Runtime 可运行

可以启动 Neura：

```bash
neura start
```

可以查看状态：

```bash
neura status
```

## 3.2 可以输入信息

可以通过 CLI 输入内容：

```bash
neura input "Neura 是一个无 UI 的智能体运行时"
```

## 3.3 可以处理信息

Neura 能够生成：

```text
摘要
标签
是否记忆
处理结果
```

## 3.4 可以保存记忆

处理后的重要信息可以写入 SQLite。

## 3.5 可以查询记忆

用户可以查询已有记忆：

```bash
neura memory list
neura memory search "插件"
```

## 3.6 可以输出结果

Neura 可以在需要表达时创建 OutputEvent，并通过 CLI 输出插件表达信息。

## 3.7 可以查看插件状态

用户可以查看：

```bash
neura plugins list
```

## 3.8 可以记录日志

每次输入、处理、记忆和输出表达都应该有日志。
